Tactical Link Runbook

A DIL demo you can stand up, break, and tear down in a single day: three EC2 instances, one shaped and lossy link, a video stream that plays clean until injected traffic drowns it.

Objective
Show video freeze at the receiver caused by traffic saturating a bandwidth-constrained, tactical-radio-like link.
Platform
AWS — 1 VPC, 3 subnets, 3 EC2 instances (Ubuntu 22.04)
Method
tc/netem for shaping, ffmpeg for video, iperf3 for the flood
Teardown
Full stack removable in under 5 minutes (Phase 05)

The trick to a clean demo is a middlebox: a third instance that sits on the path between the video source and the receiver and does nothing but shape and, later, absorb traffic. Neither endpoint knows it's there.

Why this works in a VPC A route table's local route for the VPC CIDR is normally unbeatable — but a route with a more specific destination (a /32 for one instance's private IP) takes precedence over it. Point that /32 at the shaper's network interface in both subnets' route tables, and every packet between source and receiver is forced through it, even though all three sit in one VPC.
00Provision

Stand up the VPC, three subnets, three instances, and the security group. Run from a machine with AWS CLI v2 configured and an existing key pair.

local $
export AWS_REGION=us-east-1
export KEY_NAME=your-existing-keypair
export AZ=${AWS_REGION}a

# VPC + IGW
export VPC_ID=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 \
  --query 'Vpc.VpcId' --output text --region $AWS_REGION)
aws ec2 create-tags --resources $VPC_ID --tags Key=Name,Value=dil-demo --region $AWS_REGION
export IGW_ID=$(aws ec2 create-internet-gateway --query 'InternetGateway.InternetGatewayId' \
  --output text --region $AWS_REGION)
aws ec2 attach-internet-gateway --vpc-id $VPC_ID --internet-gateway-id $IGW_ID --region $AWS_REGION

# Three subnets: source, shaper, receiver
export SUBNET_SRC=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.1.0/24 \
  --availability-zone $AZ --query 'Subnet.SubnetId' --output text --region $AWS_REGION)
export SUBNET_SHAPE=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.2.0/24 \
  --availability-zone $AZ --query 'Subnet.SubnetId' --output text --region $AWS_REGION)
export SUBNET_RCV=$(aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.3.0/24 \
  --availability-zone $AZ --query 'Subnet.SubnetId' --output text --region $AWS_REGION)

for s in $SUBNET_SRC $SUBNET_SHAPE $SUBNET_RCV; do
  aws ec2 modify-subnet-attribute --subnet-id $s --map-public-ip-on-launch --region $AWS_REGION
done
local $
# One route table per subnet, each with an internet route (for SSH/updates)
for pair in "SRC:$SUBNET_SRC" "SHAPE:$SUBNET_SHAPE" "RCV:$SUBNET_RCV"; do
  name=${pair%%:*}; sn=${pair##*:}
  rtb=$(aws ec2 create-route-table --vpc-id $VPC_ID --query 'RouteTable.RouteTableId' \
    --output text --region $AWS_REGION)
  aws ec2 create-route --route-table-id $rtb --destination-cidr-block 0.0.0.0/0 \
    --gateway-id $IGW_ID --region $AWS_REGION
  aws ec2 associate-route-table --route-table-id $rtb --subnet-id $sn --region $AWS_REGION
  export RTB_$name=$rtb
done

# Security group: SSH from you, everything internal for the demo traffic
export SG_ID=$(aws ec2 create-security-group --group-name dil-demo-sg \
  --description "DIL demo" --vpc-id $VPC_ID --query 'GroupId' --output text --region $AWS_REGION)
export MY_IP=$(curl -s ifconfig.me)/32
aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 22 \
  --cidr $MY_IP --region $AWS_REGION
aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol -1 \
  --cidr 10.0.0.0/16 --region $AWS_REGION
local $
# Latest Ubuntu 22.04 AMI, then launch all three
export AMI_ID=$(aws ssm get-parameters --names \
  /aws/service/canonical/ubuntu/server/22.04/stable/current/amd64/hvm/ebs-gp2/ami-id \
  --query 'Parameters[0].Value' --output text --region $AWS_REGION)

launch() { aws ec2 run-instances --image-id $AMI_ID --instance-type t3.small \
  --key-name $KEY_NAME --subnet-id $1 --security-group-ids $SG_ID \
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=$2}]" \
  --query 'Instances[0].InstanceId' --output text --region $AWS_REGION; }

export INSTANCE_SRC=$(launch $SUBNET_SRC dil-source)
export INSTANCE_SHAPE=$(launch $SUBNET_SHAPE dil-shaper)
export INSTANCE_RCV=$(launch $SUBNET_RCV dil-receiver)

aws ec2 wait instance-running --instance-ids $INSTANCE_SRC $INSTANCE_SHAPE $INSTANCE_RCV --region $AWS_REGION

# Pull back the IPs and the shaper's ENI id — save these, every later phase needs them
aws ec2 describe-instances --instance-ids $INSTANCE_SRC $INSTANCE_SHAPE $INSTANCE_RCV \
  --query 'Reservations[].Instances[].[Tags[?Key==`Name`].Value|[0],PublicIpAddress,PrivateIpAddress,NetworkInterfaces[0].NetworkInterfaceId]' \
  --output table --region $AWS_REGION
Watch for t3.small, not t3.micro — the shaper needs headroom to push a video stream and an iperf3 flood through tc without the instance itself becoming the bottleneck.
01Force the route

Point source→receiver and receiver→source traffic at the shaper's ENI, and let the shaper actually forward it.

local $
# Fill in from the table above
export ENI_SHAPE=eni-xxxxxxxxxxxxxxxxx
export IP_SRC_PRIV=10.0.1.x
export IP_RCV_PRIV=10.0.3.x

# Critical: AWS drops anything not addressed to the instance unless this is off
aws ec2 modify-instance-attribute --instance-id $INSTANCE_SHAPE \
  --no-source-dest-check --region $AWS_REGION

# Specific /32 routes beat the VPC's local route
aws ec2 create-route --route-table-id $RTB_SRC --destination-cidr-block ${IP_RCV_PRIV}/32 \
  --network-interface-id $ENI_SHAPE --region $AWS_REGION
aws ec2 create-route --route-table-id $RTB_RCV --destination-cidr-block ${IP_SRC_PRIV}/32 \
  --network-interface-id $ENI_SHAPE --region $AWS_REGION
shaper $
sudo sysctl -w net.ipv4.ip_forward=1
echo 'net.ipv4.ip_forward=1' | sudo tee -a /etc/sysctl.conf
source $
traceroute $IP_RCV_PRIV
# expect exactly one hop: the shaper's private IP
Gotcha If traceroute shows a direct hop instead of routing via the shaper, the /32 route didn't win — double check it's in the source's route table pointing at the shaper, and that source/dest check is actually off (it doesn't take effect retroactively on in-flight connections; reconnect after changing it).
02Shape the link

Cap the shaper's egress to a tactical-radio-like ceiling and add delay, jitter, and loss with netem.

shaper $
sudo apt-get update && sudo apt-get install -y iproute2

sudo tc qdisc add dev eth0 root handle 1: htb default 10
sudo tc class add dev eth0 parent 1: classid 1:10 htb rate 256kbit ceil 256kbit
sudo tc qdisc add dev eth0 parent 1:10 handle 10: netem \
  delay 100ms 20ms distribution normal loss 2% 25%

# check it took
tc -s qdisc show dev eth0

256kbit/s is a deliberate choice — slow enough that a low-bitrate video stream alone plays back cleanly but with visible latency, and slow enough that even a modest flood saturates it completely. Reset any time with:

shaper $
sudo tc qdisc del dev eth0 root

For the "intermittent" half of DIL — comms windows that drop out entirely — toggle to full loss on a timer instead of a constant rate:

shaper $
cat <<'EOF' > ~/blackout.sh
#!/bin/bash
while true; do
  sudo tc qdisc change dev eth0 parent 1:10 handle 10: netem delay 100ms 20ms loss 2% 25%
  sleep 45
  sudo tc qdisc change dev eth0 parent 1:10 handle 10: netem loss 100%
  sleep 8
done
EOF
chmod +x ~/blackout.sh
Watch for tc rules do not survive a reboot or a stop/start cycle — if the instance restarts for any reason, rerun the shaping commands before the demo.
03Stream video

Get a clean, low-bitrate UDP stream playing over the shaped link before anything is injected — that clean baseline is the "before" half of the demo.

source + receiver $
sudo apt-get install -y ffmpeg
wget -O clip.mp4 https://download.blender.org/peach/bigbuckbunny_movies/BigBuckBunny_320x180.mp4
# any local mp4 works fine if that URL is unreachable

MPEG-TS over UDP instead of raw RTP — it self-describes the stream, so there's no SDP file to shuttle between hosts, and it's still UDP, so it still stalls realistically under loss.

receiver $
ffplay -fflags nobuffer udp://0.0.0.0:5004
source $
ffmpeg -re -stream_loop -1 -i clip.mp4 -an -c:v libx264 -preset veryfast \
  -tune zerolatency -b:v 200k -f mpegts udp://$IP_RCV_PRIV:5004

Confirm it plays — slow to start, a little laggy, but smooth and unbroken. If it isn't clean here, everything downstream will look like noise instead of a clear before/after.

04Inject & break it

Push a UDP flood across the same shaped link the video is using, and watch the queue — and the picture — fall apart.

source + receiver $
sudo apt-get install -y iperf3
receiver $
iperf3 -s
source $ (second terminal)
# 5 Mbps against a 256 kbit ceiling — roughly 20x oversubscribed, so
# the effect is unmistakable rather than marginal
iperf3 -c $IP_RCV_PRIV -u -b 5M -t 300

With the flood running alongside the video stream, watch the queue on the shaper build and drop packets:

shaper $
watch -n1 tc -s qdisc show dev eth0
# the "dropped" counter under the netem line is the story —
# it should be climbing fast the moment iperf3 starts

The receiver's ffplay window stalls and freezes within a few seconds. Stop the iperf3 client and it recovers on its own — that recovery is worth showing too, since it's the difference between a degraded link and a dead one.

05Rehearse & tear down

Run it twice end to end before the live demo, then know exactly how to shut it off.

Go / no-go, before you present:

  • Baseline clip plays clean over the shaped link with nothing else running
  • iperf3 flood visibly freezes the picture within ~5–10 seconds, every time
  • Stopping the flood lets playback recover without restarting anything
  • tc rules re-applied if either instance was stopped/started since Phase 02
  • Optional: blackout.sh rehearsed if you want the intermittency angle too
local $
# Stop paying for compute without losing the setup (good for an overnight pause)
aws ec2 stop-instances --instance-ids $INSTANCE_SRC $INSTANCE_SHAPE $INSTANCE_RCV --region $AWS_REGION

# Full teardown once the demo is done
aws ec2 terminate-instances --instance-ids $INSTANCE_SRC $INSTANCE_SHAPE $INSTANCE_RCV --region $AWS_REGION
aws ec2 wait instance-terminated --instance-ids $INSTANCE_SRC $INSTANCE_SHAPE $INSTANCE_RCV --region $AWS_REGION
aws ec2 delete-security-group --group-id $SG_ID --region $AWS_REGION
# subnets first: a route table can't be deleted while still associated with one
for sn in $SUBNET_SRC $SUBNET_SHAPE $SUBNET_RCV; do aws ec2 delete-subnet --subnet-id $sn --region $AWS_REGION; done
for rtb in $RTB_SRC $RTB_SHAPE $RTB_RCV; do aws ec2 delete-route-table --route-table-id $rtb --region $AWS_REGION; done
aws ec2 detach-internet-gateway --internet-gateway-id $IGW_ID --vpc-id $VPC_ID --region $AWS_REGION
aws ec2 delete-internet-gateway --internet-gateway-id $IGW_ID --region $AWS_REGION
aws ec2 delete-vpc --vpc-id $VPC_ID --region $AWS_REGION
Built for a single working day. Stretch goals if time allows: a fourth "jammer" instance so the flood isn't sharing a box with the video source, or swap the fixed 256kbit cap for a script that ramps it down mid-demo to simulate a link degrading in real time.
